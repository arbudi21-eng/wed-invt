# Design upgrade brief — intro sections, cover photo, unique gallery

Read this fully before editing. You own ONLY the two design files assigned to you.
Do NOT edit `lib/core.js`, `generate.js`, `index.html`, `templates/*`, `sites/*` or any other design.

## Shared build behaviour you can rely on

`lib/core.js` now injects, into every built page:

1. `CFG.cover`, `CFG.man`, `CFG.woman` when the studio/generator has matching files
   (`assets/cover-1.jpg`, `assets/man-1.jpg`, `assets/woman-1.jpg`).
2. A tiny script that, for every `[data-photo="cover|man|woman"]` element, removes the
   placeholder and sets `background-image` to the real photo (adds class `has-photo`).
3. For the cover it also inserts `<div class="cover-bg" aria-hidden="true"></div>` inside
   `#cover` and sets its background image (adds class `has-photo` on `#cover`).
4. Base CSS for `.cover-bg` (absolute, inset 0, z-index:-1, cover, centred) and a default
   dark scrim via `.cover-bg::after`. **Override `.cover-bg::after` per design** for a
   unique cover treatment.
5. `core.build` still replaces the literal words `Amara` and `Dewa` with the real couple
   names everywhere. `Amara` = the woman / bride, `Dewa` = the man / groom.
   Keep using those literals in the new sections so real names flow through.

When no photos exist nothing is inserted, so every new visual MUST degrade gracefully to
the design's existing gradient/illustration look.

## Task 3 — unique gallery structure per design

The section literally titled Gallery is:

```html
<section id="album" class="rv"><h2 data-t="gl">Gallery</h2><div class="mas" id="mas"></div></section>
```

Keep the `<section id="album">`, `<h2 data-t="gl">Gallery</h2>` and a root
`<div id="mas">` (the id is required). Replace the `.mas` class with your own gallery
class. Rewrite the gallery building JS block (currently starting
`const ms=$('#mas'),lb=$('#lb'),lc=$('#lc');`) so it renders `CFG.album` into your own
structure.

Hard requirements for the gallery:
- distinct DOM + CSS layout per design (see archetypes below) — must not be a masonry
  `columns:` layout any more.
- every item is keyboard reachable (`tabindex="0"`, `role="button"`, aria-label) and
  opens the existing lightbox (`#lb`, `#lc`, `#lx`) on click / Enter / Space.
- each item keeps the gradient fallback (`--g` custom property or inline background) and
  shows `a.src` as an `<img>` when present, exactly like the old code.
- works with 3–12 photos without gaps or clipping.
- responsive at 390 / 768 / 1280 px.
- caption is optional; if you show one, use `a.cap` only when it exists (album items
  normally have no caption).

Assigned gallery archetypes (do exactly these two, one per design):

- **01** contact-sheet filmstrip: horizontal scroll, uniform 4/5 frames, sprocket-hole
  strip, frame numbers, snap scrolling.
- **02** editorial ledger: full-width rows, one large photo per row alternating
  left/right with an index numeral and thin rule.
- **03** botanical scatter: 3-column grid of rotated cards at varying vertical offsets,
  leaf/flower marks, hover lift.
- **04** single spotlight: one large featured photo plus a thumbnail rail below; clicking
  a thumbnail swaps the feature (and still opens lightbox on the feature).
- **05** strict contact grid: uniform square 3-column grid, hairline gutters, no radius,
  numeric labels.
- **06** constellation: circular frames positioned along a dotted arc / alternating
  offsets, star marks between them.
- **07** arch colonnade: two offset columns of tall arched frames with generous space.
- **08** polaroid fan: overlapping, slightly rotated polaroids with tape corners; hover
  straightens and lifts.
- **09** deco triptych: symmetric 3-panel frames with double gold borders, centre panel
  taller.
- **10** batik mosaic: CSS grid mosaic with one large feature tile and small tiles around
  it, pattern seams.
